# М70 — QR-регистрация

GitHub Pages отвечает только за распознавание QR. Запись прихода выполняет
авторизованное HTML-приложение Google Apps Script через `google.script.run`.

## Почему нужен Apps Script bridge

HTML Service Apps Script работает в изолированном iframe. Поэтому GitHub Pages
не может напрямую вызвать `google.script.run`. Авторизованный регистратор сначала
открывает Apps Script web app, а оно по кнопке открывает сканер в отдельном окне.
Окна обмениваются сообщениями только после проверки `origin`, `source`, случайного
`channelId` и RSA-подписи короткоживущей bridge-сессии.

`postMessage` здесь не является авторизацией. Доступ обеспечивают одновременно:

- вход в Google и запуск web app от имени пользователя;
- серверный allowlist `REGISTRAR_EMAILS`;
- доступ регистратора к самой Google Таблице;
- серверная подпись bridge-сессии приватным ключом Apps Script;
- проверка каждого серверного метода, включая резервный `checkIn(token)`.

В Git хранится только публичный ключ проверки. Приватный RSA-ключ нельзя добавлять
в репозиторий, исходный код, сообщения или URL.

Токен передаётся только в теле сообщения между уже открытыми окнами, затем в
`google.script.run`. Он не попадает в URL, репозиторий, DOM, сообщения об ошибках
или серверные логи.

## Развёртывание Apps Script

1. В привязанном к таблице Apps Script проекте сохраните резервную копию текущего
   `checkIn(token)`.
2. Добавьте файлы [`apps-script/Code.gs`](apps-script/Code.gs) и
   [`apps-script/Registrar.html`](apps-script/Registrar.html). `Code.gs` содержит
   полный вариант `checkIn(token)` и не меняет значения токенов в столбце F.
3. В **Project Settings → Script properties** создайте:
   - `SPREADSHEET_ID` — ID таблицы;
   - `SHEET_NAME` — точное имя листа;
   - `REGISTRAR_EMAILS` — ровно два разрешённых Google email через запятую;
   - `BRIDGE_PRIVATE_KEY` — полный PEM приватного RSA-ключа, выданный отдельно и
     не добавляемый в Git;
   - `CHECKED_IN_STATUS` — существующее значение статуса прихода (необязательно,
     по умолчанию `Пришёл`).
4. Дайте обоим регистраторам права редактора на таблицу. Персональные данные и
   токены не публикуйте.
5. **Deploy → New deployment → Web app**:
   - Execute as: **User accessing the web app**;
   - Who has access: **Anyone with Google account** (или только ваш Workspace
     domain, если оба регистратора находятся в нём);
   - никогда не выбирайте anonymous access.
6. Каждый регистратор один раз открывает URL web app и подтверждает необходимые
   Google permissions. Работа всегда начинается с этого URL, затем с кнопки
   **Открыть QR-сканер**.
7. После изменений Apps Script создавайте новую версию deployment. URL GitHub
   Pages изменять не требуется.

## Ручной acceptance-тест перед мероприятием

Используйте только тестовые строки или билеты, для которых допустимо очистить
статус после проверки. Не присылайте токены в issue или PR.

1. Откройте GitHub Pages напрямую: режим должен остаться тестовым, а связь с
   Apps Script — отклоняться.
2. Откройте web app под каждым из двух разрешённых аккаунтов, нажмите **Открыть
   QR-сканер**, затем **Проверить связь**. Оба аккаунта должны получить успешный
   ответ. Третий аккаунт не должен открыть web app.
3. На телефоне A считайте неиспользованный билет: в D должен появиться статус, в
   E — время, а на телефоне — «Приход отмечен».
4. Считайте этот билет повторно или на телефоне B: ответ должен быть «Билет уже
   использован», без изменения счётчика подтверждений.
5. Для отдельного тестового билета одновременно наведите два телефона. Ровно один
   запрос должен получить `checked_in`, второй — `already_used`.
6. Отключите сеть перед ответом сервера: «Подтверждено» не должно увеличиться.
   После восстановления сети используйте **Повторить отправку**.
7. Повторите один проход через **Выбрать фотографию QR** и убедитесь, что камера
   после этого продолжает работать.

Если существующий статус отличается от `Пришёл`, задайте точное значение в
`CHECKED_IN_STATUS`. Повтор определяется по времени в столбце E или этому статусу.
`LockService.getScriptLock()` охватывает поиск, проверку и запись, поэтому два
телефона не смогут одновременно подтвердить один билет.

## Резервное распознавание по фотографии

Кнопка **Выбрать фотографию QR** использует ту же проверку и тот же серверный
маршрут, что и камера. Публично открытая GitHub Pages остаётся в тестовом режиме:
она распознаёт уникальные QR, но ничего не записывает.

## Локальная проверка

```sh
npm test
npm run check
python3 -m http.server 4173
```

Откройте `http://127.0.0.1:4173`. Камера в браузере требует secure context;
localhost считается безопасным, а опубликованная страница работает по HTTPS.

## Диагностика

- **Библиотека не загрузилась** — проверить интернет/CDN и обновить страницу.
- **Нет авторизованной связи** — открыть сканер только кнопкой из Apps Script.
- **Сервер не ответил** — приход не подтверждён; после проверки сети нажать
  **Повторить отправку**.
- **Билет уже использован** — сервер нашёл время прихода или статус в таблице.
- **Доступ разрешён только регистраторам** — проверить Google-аккаунт, allowlist,
  режим deployment и доступ к таблице.
