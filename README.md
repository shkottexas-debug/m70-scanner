# М70 — QR-регистрация

GitHub Pages отвечает только за распознавание QR. Запись прихода выполняет
авторизованное HTML-приложение Google Apps Script через `google.script.run`.

## Почему нужен Apps Script bridge

HTML Service Apps Script работает в изолированном iframe. Поэтому GitHub Pages
не может напрямую вызвать `google.script.run`. Авторизованный регистратор сначала
открывает Apps Script web app, а оно по кнопке открывает сканер в отдельном окне.
Окна обмениваются сообщениями только после проверки `origin`, `source`, случайного
`channelId` и RSA-подписи короткоживущей bridge-сессии. Apps Script сам многократно
отправляет подписанный handshake в только что открытое окно; `document.referrer`
не используется. Пятиминутная сессия проверяется с обеих сторон и автоматически
продлевается до истечения.

`postMessage` здесь не является авторизацией. Доступ обеспечивают одновременно:

- вход в Google и запуск web app от имени пользователя;
- серверный allowlist `REGISTRAR_EMAILS`;
- доступ регистратора к самой Google Таблице;
- серверная подпись bridge-сессии приватным ключом Apps Script;
- проверка каждого серверного метода, включая резервный `checkIn(token)`.

В Git хранится только публичный ключ проверки. Приватный RSA-ключ нельзя добавлять
в репозиторий, исходный код, сообщения или URL.

Токен передаётся только в теле сообщения между уже открытыми окнами, затем в
`google.script.run`. Он не попадает в URL, репозиторий, DOM, сообщения об ошибках
или серверные логи.

Это решение всё равно требует проверки на реальных телефонах. Apps Script
HTML Service запускается в sandboxed iframe; поддержка popup разрешена платформой,
но сохранение `WindowProxy` зависит от браузера, popup-policy и заголовков сайта.
Камера остаётся на GitHub Pages: Google отдельно предупреждает, что чувствительные
Web API, включая `getUserMedia`, могут не работать внутри HTML Service iframe.
Если матрица браузеров ниже не проходит, безопасный запасной вариант — отдельный
same-origin backend со входом регистраторов и серверным вызовом `checkIn`; нельзя
заменять его публичным Apps Script endpoint или доверять одному `postMessage`.

## Допустимые статусы билета

Приход записывается только из исходного статуса `Зарегистрирован`.
`Отменён`/`Аннулирован` возвращает отказ `cancelled`, заблокированный билет —
`blocked`, а `Резерв`, `Подтвердил` и любой другой статус — `not_eligible`.
Ни один отказ не меняет таблицу. Повтор после уже выполненной записи возвращает
`already_used`.

## Условия подключения рабочего Apps Script

Код в `apps-script/` подготовлен для ревью, но его нельзя загружать в рабочий
проект до отдельного подтверждения следующих пунктов:

- найден и однозначно идентифицирован именно production Apps Script project;
- создана резервная версия текущего deployment и записан его deployment ID;
- публичный ключ в `scanner.js` проверен против приватного ключа production;
- тестовый приватный ключ не переносится в production автоматически;
- `SPREADSHEET_ID`, `SHEET_NAME`, `CHECKED_IN_STATUS` и `REGISTRAR_EMAILS`
  проверены без публикации их значений;
- выбран способ ограничения доступа регистраторов к персональным данным.

При `USER_ACCESSING` Apps Script обращается к таблице от имени регистратора,
поэтому регистратору обычно нужен доступ к самой таблице. Для основной таблицы с
ФИО и email это риск конфиденциальности. Предпочтительный вариант — отдельная
неперсональная таблица check-in либо отдельный серверный слой, выполняющий запись
от имени владельца и проверяющий allowlist. Это изменение нельзя подменять
анонимным web app или публичным API.

## Развёртывание Apps Script

1. В привязанном к таблице Apps Script проекте сохраните резервную копию текущего
   `checkIn(token)`.
2. Добавьте файлы [`apps-script/Code.gs`](apps-script/Code.gs) и
   [`apps-script/Registrar.html`](apps-script/Registrar.html). `Code.gs` содержит
   полный вариант `checkIn(token)` и не меняет значения токенов в столбце F.
3. В **Project Settings → Script properties** создайте:
   - `SPREADSHEET_ID` — ID таблицы;
   - `SHEET_NAME` — точное имя листа;
   - `REGISTRAR_EMAILS` — ровно два разрешённых Google email через запятую;
   - `BRIDGE_PRIVATE_KEY` — полный PEM приватного RSA-ключа, выданный отдельно и
     не добавляемый в Git;
   - `CHECKED_IN_STATUS` — существующее значение статуса прихода (необязательно,
     по умолчанию `Пришёл`).
4. Не выдавайте регистраторам доступ к основной таблице с персональными данными.
   Рекомендуется отдельная рабочая таблица посещаемости только со столбцами
   статус (D), время (E), токен (F) и, при необходимости, неперсональным номером
   билета. Укажите её в `SPREADSHEET_ID` и дайте двум регистраторам права редактора
   только на неё. Синхронизацию с закрытой основной таблицей выполняйте от имени
   владельца отдельно.
5. **Deploy → New deployment → Web app**:
   - Execute as: **User accessing the web app**;
   - Who has access: **Anyone with Google account** (или только ваш Workspace
     domain, если оба регистратора находятся в нём);
   - никогда не выбирайте anonymous access.
6. Каждый регистратор один раз открывает URL web app и подтверждает необходимые
   Google permissions. Работа всегда начинается с этого URL, затем с кнопки
   **Открыть QR-сканер**.
7. После изменений Apps Script создавайте новую версию deployment. URL GitHub
   Pages изменять не требуется.

## Безопасная проверка M70-006 без записи

После загрузки серверного кода в отдельную тестовую или подтверждённую рабочую
версию владелец может вручную вызвать `validateTicketWithoutCheckIn(token)` из
редактора Apps Script. Функция только читает D–F и возвращает одну категорию:
`eligible`, `already_used`, `cancelled`, `blocked`, `not_eligible` или
`not_found`. Она не меняет D/E, не возвращает ID, ФИО, email или токен и не
участвует в обычном потоке сканера. Токен M70-006 нельзя вставлять в issue, PR,
логи или скриншоты.

## Обязательные ручные проверки перед мероприятием

Используйте только тестовые строки или билеты, для которых допустимо очистить
статус после проверки. Не присылайте токены в issue или PR.

1. На реальном iPhone/iPad с актуальным Safari и Android с актуальным Chrome
   открыть Apps Script web app, разрешить popup и проверить, что отдельный сканер
   подключается. Повторить после закрытия окна, смены вкладки и блокировки экрана.
2. В DevTools/удалённой отладке подтвердить фактический origin Apps Script
   (`script.google.com` либо один HTTPS-host `*.googleusercontent.com`), отсутствие
   ошибок `postMessage`, разрыва `window.opener`/`WindowProxy` и заголовка
   `Cross-Origin-Opener-Policy`, который разрывает связь окон.
3. Открыть GitHub Pages напрямую: режим остаётся тестовым, запросы к Apps Script
   не отправляются. Проверить, что URL сканера не содержит токена билета,
   `channelId`, подписи, email или иных полномочий.
4. Под каждым из двух разрешённых аккаунтов открыть web app, затем **Открыть
   QR-сканер** и **Проверить связь**. Третий аккаунт и режим инкогнито без входа
   должны получить отказ. Проверить, что регистраторы не видят основную таблицу с
   ФИО, телефонами, email и другими персональными данными.
5. Оставить связку открытой более пяти минут. Без перезапуска камеры проверить
   автоматическое продление, затем временно оборвать сеть на время продления:
   после истечения сканер обязан перейти в тестовый режим и не отправлять билет.
6. Для тестовой строки проверить исходный статус `Зарегистрирован`: в D появляется
   статус прихода, в E — время, на телефоне — «Приход отмечен».
7. Отдельно проверить `Отменён`, `Аннулирован`, `Заблокирован`, `Резерв`,
   `Подтвердил` и произвольный недопустимый статус. Должен отображаться
   соответствующий отказ, D и E не меняются.
8. Дважды считать использованный билет, включая второй телефон: каждый повтор
   показывает «Билет уже использован», время и число подтверждённых проходов не
   увеличиваются.
9. Одновременно считать один новый тестовый билет двумя телефонами. Ровно один
   получает `checked_in`, второй — `already_used`; в таблице одна запись времени.
   Повторить не менее десяти раз на разных тестовых строках.
10. Отключить сеть сразу после сканирования, до ответа сервера. Ложного успешного
    сообщения и увеличения счётчика быть не должно. Восстановление сети и QR,
    оставшийся в кадре, не должны отправлять новый запрос. После восстановления
    нажать **Повторить отправку** и проверить итог по таблице: `checked_in` либо
    `already_used`, но только одна запись прихода. Учтите: уже переданный
    `google.script.run` нельзя отменить на стороне сканера, поэтому его поздний
    положительный ответ может означать завершение первоначального запроса.
11. Без перезапуска камеры считать два разных QR подряд, затем один из них снова.
    Счётчик распознанных увеличивается только для уникальных QR.
12. Проверить резервный путь **Выбрать фотографию QR** для нового, повторного и
    отменённого билета; после выбора фотографии непрерывная камера возобновляется.
13. Провести пробный поток не менее 120 тестовых сканирований с двумя телефонами,
    сверить число уникальных записей времени в таблице и отсутствие дублей,
    пропусков и персональных данных в консоли/журналах.

Если существующий статус отличается от `Пришёл`, задайте точное значение в
`CHECKED_IN_STATUS`. Повтор определяется по времени в столбце E или этому статусу.
`LockService.getScriptLock()` охватывает поиск, проверку и запись, поэтому два
телефона не смогут одновременно подтвердить один билет.

## Порядок публикации и откат

1. Сначала развернуть серверный код отдельной новой версией Apps Script, не
   переключая действующий deployment.
2. Проверить новую версию только на отдельной тестовой таблице и двух тестовых
   аккаунтах.
3. Проверить `validateTicketWithoutCheckIn` на M70-006 без изменения D/E.
4. Только после письменного подтверждения переключить production deployment и
   затем опубликовать GitHub Pages из проверенного коммита.
5. Сохранить SHA предыдущего Pages и номер предыдущей версии Apps Script.

При неисправности вернуть deployment на предыдущую версию Apps Script и
восстановить предыдущий SHA Pages через обычный revert-коммит. Не использовать
force-push и не удалять журналы диагностики до завершения разбора.

Защищённые диапазоны и скрытые листы Google Sheets не являются разграничением
конфиденциальности: редактор может скопировать или экспортировать таблицу. Поэтому
персональные данные нужно физически держать в другой, не расшаренной регистраторам
таблице.

## Резервное распознавание по фотографии

Кнопка **Выбрать фотографию QR** использует ту же проверку и тот же серверный
маршрут, что и камера. Публично открытая GitHub Pages остаётся в тестовом режиме:
она распознаёт уникальные QR, но ничего не записывает.

## Локальная проверка

```sh
npm test
npm run check
python3 -m http.server 4173
```

Откройте `http://127.0.0.1:4173`. Камера в браузере требует secure context;
localhost считается безопасным, а опубликованная страница работает по HTTPS.

## Диагностика

- **Библиотека не загрузилась** — проверить интернет/CDN и обновить страницу.
- **Нет авторизованной связи** — открыть сканер только кнопкой из Apps Script.
- **Сервер не ответил** — приход не подтверждён; после проверки сети нажать
  **Повторить отправку**.
- **Сессия регистратора истекла** — новые билеты не отправляются до получения
  новой подписанной сессии; проверьте окно Apps Script и сеть.
- **Билет отменён/заблокирован** — сервер отклонил проход без изменения D и E.
- **Билет уже использован** — сервер нашёл время прихода или статус в таблице.
- **Доступ разрешён только регистраторам** — проверить Google-аккаунт, allowlist,
  режим deployment и доступ к таблице.
